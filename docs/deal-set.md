# Набор «связанные документы одной сделки»: tests/deal/

Синтетический набор для главного сценария второй версии Маски: человек обезличивает несколько документов одной сделки, и одна фирма должна получить одну метку во всех файлах. Настоящих выгрузок 1С и пар «договор и акт» в открытом доступе найти не удалось, поэтому набор собран вручную. Все названия, имена, телефоны, адреса и почтовые ящики выдуманные (почта в доменах `.example`). ИНН (10 и 12 цифр), ОГРН, ОГРНИП и ключ расчётного счёта посчитаны по настоящим алгоритмам. Названия банков и БИК взяты из открытых справочников, это единственные не выдуманные значения, и по правилам Маски банки остаются.

Файлы читает стенд tests/harness-files.mjs (описание в docs/harness-files.md). Разметка лежит в tests/deal.json, формат тот же: `must_types`, `keep`.

## Как пересобрать

```
python3 tests/deal/make.py
```

Скрипт пишет все файлы в tests/deal/ и заново создаёт tests/deal.json. Нужен только Python 3 и `soffice`. docx собираются из XML через zipfile, потому что модуля Writer на машине нет. xlsx собираются из flat ODS (.fods во временной папке) командой `soffice --headless --convert-to xlsx`. Страницы docx не считались (Writer нет), по объёму текста договор подряда занимает примерно три страницы.

## Сеанс с одним сейфом

Стенд прогоняет набор и сеансом: файлы идут по порядку разметки с одним сейфом, как их обезличивает человек. В `tests/deal.json` лежит словарь из 86 сущностей с написаниями (`entities`), разметка файлов в `files`. Стенд считает долю сущностей с одной меткой во всех файлах, расщеплённые (одна сущность, несколько меток) и склеенные (одна метка у разных сущностей). Описание в docs/safe.md.

Замер 04.10.2026: одна метка во всех файлах у 86 сущностей из 86, у сущностей из двух файлов и больше 44 из 44, расщеплённых и склеенных нет. С новым сейфом на каждом файле (`--fresh`, как до сейфа) 26 из 86 и 3 из 44.

`make.py` словарь не пишет: при пересборке набора `entities` и правки дат в `keep` надо перенести в новый `tests/deal.json`.
