# Общий сейф и русские метки

Маска 2 ведёт сейф отдельным файлом. В нём лежат метки и настоящие значения всех документов одного клиента или дела, а также свои слова пользователя. Документ, обезличенный с сейфом, получает прежние метки для уже известных значений. Ответ нейросети возвращается по тому же сейфу.

Код сейфа лежит в `src/safe.mjs`: чистые функции без браузера, тесты на Node в `tests/safe.test.mjs`. Сборка вставляет модуль в `index.html` первым, его функции зовут правила (`mask`) и интерфейс.

## Метки

Метка состоит из короткого русского слова заглавными и номера в квадратных скобках: `[ОРГ_1]`, `[ФИО_2]`. Номер идёт по типу с единицы. Таблица слов одна, `TAG_WORD` в `src/safe.mjs`:

| Тип | Метка | Тип | Метка |
|---|---|---|---|
| PERSON | `[ФИО_1]` | ACCOUNT | `[СЧЁТ_1]` |
| ORG | `[ОРГ_1]` | CARD | `[КАРТА_1]` |
| INN | `[ИНН_1]` | ADDRESS | `[АДРЕС_1]` |
| KPP | `[КПП_1]` | PHONE | `[ТЕЛ_1]` |
| OGRN | `[ОГРН_1]` | EMAIL | `[ПОЧТА_1]` |
| BIK | `[БИК_1]` | NICK | `[НИК_1]` |
| SNILS | `[СНИЛС_1]` | ID (номер документа) | `[ДОГОВОР_1]` |
| PASSPORT | `[ПАСПОРТ_1]` | AMOUNT | `[СУММА_1]` |
| DOB (дата рождения) | `[РОЖДЕНИЕ_1]` | DATE (дата выдачи паспорта) | `[ДАТА_1]` |
| TERM (своё слово) | `[СЛОВО_1]` | | |

Сомнительное из окна проверки получает свои метки. Маска прячет его, хотя не уверена, что это нужно, а человек может снять метку.

| Тип | Метка | Что это |
|---|---|---|
| NAME | `[НАЗВАНИЕ_1]` | слово с заглавной буквы, которого нет в словаре Маски, или название в кавычках без ООО и АО |
| NUM | `[НОМЕР_1]` | длинное число без подписи: от восьми цифр подряд (в таблицах от девяти) или от семи с пробелами и дефисами |
| AT | `[КОНТАКТ_1]` | всё со знаком @, что не узнано как почта или ник |

Тип ID объединяет номера договоров, актов, счетов, табельные номера и полисы, поэтому табельный номер тоже получит `[ДОГОВОР_N]`. Отдельного типа для них правила не дают. Внутренние типы (PERSON, ORG и так далее) остались прежними, разметка наборов в поле `types` на них ссылается и правок не потребовала. `LABEL` в `index.html` по-прежнему даёт подписи типов для экрана.

Старые метки первой версии `#ORG_1#` новая Маска не выдаёт. Если они лежат в открытом сейфе, обратная подстановка их понимает, а новые записи такого сейфа получают русские метки со следующим номером.

## Файл сейфа

Имя файла `<название сейфа>.сейф.json`, без названия `без названия.сейф.json`. Это JSON в UTF-8:

```json
{
 "format": "maska-safe",
 "version": 1,
 "name": "Каменный Мост, подряд",
 "created": "2026-10-04T10:00:00.000Z",
 "changed": "2026-10-05T09:12:44.120Z",
 "data": {
  "words": ["Складской комплекс", "проект Север-2"],
  "records": [
   {"tag": "[ОРГ_1]", "type": "ORG", "value": "ООО «Каменный Мост»",
    "forms": ["ООО «Каменный Мост»", "Общество с ограниченной ответственностью «Каменный Мост»", "Каменный Мост ООО", "Каменного Моста"],
    "keys": ["каменный мост"]},
   {"tag": "[ФИО_1]", "type": "PERSON", "value": "Белоусов Игорь Станиславович",
    "forms": ["Белоусова Игоря Станиславовича", "Белоусов И.С.", "Белоусов Игорь Станиславович"],
    "keys": ["белоусов|И"]},
   {"tag": "[ИНН_1]", "type": "INN", "value": "7816135799", "forms": ["7816135799"], "keys": ["7816135799"]}
  ]
 }
}
```

Поля:

- `format` и `version`: по ним Маска узнаёт свой файл. Файл с версией выше 1 не открывается, страница просит открыть его в новой версии.
- `name`: клиент или дело, вписывается на странице. `created` и `changed`: даты создания и последнего изменения содержимого. `changed` меняется, только когда в сейф что-то добавилось или изменились слова и название.
- `data.words`: свои слова, они же поле «Что ещё спрятать».
- `data.skip`: сомнительные слова и числа, с которых человек снял метку в окне проверки. В следующих документах с этим сейфом они не прячутся, в том числе в других падежах. Запись слова, спрятанного раньше, остаётся в `records`: ответы по прежним документам возвращаются. Сейф без этого поля читается как сейф с пустым списком.
- `data.records`: записи. `tag` метка, `type` внутренний тип, `value` значение для обратной подстановки, `forms` все встреченные написания, `keys` ключи сопоставления от правил маски.

Пароль в эту версию не входит. Записи и слова лежат в одном поле `data`, имя и даты снаружи. Для шифрования `data` заменится полем `encrypted` (алгоритм, соль, вектор, шифротекст), версия станет 2. Нынешняя Маска на файле с `encrypted` пишет «сейф защищён паролем, эта версия Маски пароли не открывает» и текущий сейф не трогает.

Чтение файла (`safeParse`) возвращает сейф или причину отказа. Причины для человека: файл повреждён и не читается; это не сейф Маски; сейф более новой версии; сейф с паролем; нет списка записей; в записи N нет метки или значения; у метки другой тип; метка записана дважды. Сейф первой версии (список `{tag, type, value, forms}` со старыми метками) тоже открывается.

## Сейф и документ

В памяти страницы два сейфа: текущий и сейф до текущего документа. Маска документа идёт от сейфа «до», поэтому повторное нажатие «Замаскировать» на том же тексте не копит лишнего. Когда загружен новый файл, нажат «Пример» или текст в поле поменялся, текущий сейф становится сейфом «до» следующего документа.

`mask(text, terms, {sums, safe})` собирает сущности документа по ключам правил, как раньше, и отдаёт их в `safeMerge`. Сущность получает метку записи сейфа, если совпало одно из:

1. найденное по сейфу написание (`safeTag`, см. ниже);
2. ключ того же типа (регистр и «ё» не важны);
3. одно из написаний того же типа без учёта регистра, кавычек и «ё»;
4. для человека: фамилия. Одинокая фамилия идёт к единственному человеку с этой фамилией в сейфе, полное ФИО к записи, где была только фамилия.

Иначе сущность получает следующий свободный номер своего типа: наибольший номер этого типа в сейфе плюс один. Новые написания и ключи дописываются к записи. Для ФИО значением записи становится полное ФИО в именительном падеже, если оно встретилось.

До сопоставления сейф добавляет находки в документ:

- свои слова сейфа ищутся, как поле «Что ещё спрятать»;
- написания из записей ищутся в тексте как есть, с границей слова. Так «по 41-КВ/2025 оплачено» прячется, хотя правила номер без слова «договор» не находят. Не ищутся: свои слова (их ищет поле), даты выдачи паспорта (совпадут с датой договора), суммы при выключенном «прятать суммы», значения короче 4 знаков и числа меньше 6 цифр;
- названия организаций из сейфа ищутся без формы и в падежах;
- фамилии людей из сейфа связывают одинокую фамилию в тексте («звонил Петрову»), если у этой фамилии в сейфе один человек.

`mask` возвращает новый сейф (`safe`) и число новых записей (`added`), исходный сейф не меняется.

## Как связываются написания

Организация. Ключ это название без формы и кавычек в нижнем регистре, «ё» как «е». Одну метку получают:

- `ООО «Каменный Мост»`, `Каменный Мост ООО`, `«Каменный Мост» ООО`, `КАМЕННЫЙ МОСТ, ООО` (форма в конце, как в выгрузках 1С);
- `Общество с ограниченной ответственностью «Каменный Мост»` и другие полные формы, которые знают правила;
- `Каменный Мост` без формы, если форма встречалась в этом документе или название есть в сейфе;
- падежные формы `Каменного Моста`, `Каменному Мосту`, `Каменным Мостом`, `Нева-Металлу`. Слово с заглавной и строчными теряет окончание (`ый`, `ий`, `ой`, `ая`, `а`, `я`, `ь` и подобные) и принимает до трёх букв. Это же действует внутри одного документа.

ИНН и название фирмы остаются разными метками: `[ИНН_1]` и `[ОРГ_1]`.

Человек. Ключ это основа фамилии и первая буква имени (`петров|И`). Одну метку получают `Петров Иван Сергеевич`, `Петрова Ивана Сергеевича`, `Петров И.С.`, `И.С. Петров`, `Петров Иван`, `Иван Петров`, `Петрову И.С.`, одна фамилия `Петрову` или `Петровым`, если человек с этой фамилией один. Женские формы `Нестеровой Аллы Викторовны` и `Нестерова А.В.` тоже. Основа срезает `-ий` и `-им`, поэтому `Мирский` и `Мирского` одна фамилия. `Ковалёва` и `Ковалева` одна запись: сейф сравнивает ключи без различия «ё» и «е».

Остальное:

| Тип | Ключ | Пример одной метки |
|---|---|---|
| телефон | последние 10 цифр | `+7 (981) 700-45-19` и `89817004519` |
| ИНН, КПП, ОГРН, БИК, счёт, карта | цифры | ИНН числом из Excel `7.816135799E9` и `7816135799` |
| почта, ник | текст в нижнем регистре | `Buh@KamenniyMost.example` и `buh@kamenniymost.example` |
| адрес | текст без пробелов, точек и запятых | `ул. Балканская, д. 20` и `ул.Балканская,д.20` |
| сумма | число и валюта | `4 896 000,00 руб.`, `4 896 000,00`, `4 896 000 руб.` |
| номер документа | текст заглавными | `41-КВ/2025` и `41-кв/2025` |
| своё слово | слово в нижнем регистре | `Север-2` и `север-2` |

Ключи почты, ника, адреса и суммы изменены в этой работе. Раньше почта и адрес шли по одним цифрам, и `ivan1@a.example` с `petr1@b.example` или два адреса с домом 20 получали одну метку. Сумма шла по тексту, и `4 896 000,00 руб.` с `4 896 000,00` получали разные.

## Что не связывается

Проверено короткими примерами, часть закреплена в `tests/safe-mask.test.mjs`.

- Падеж с беглой гласной: `Северного Ветра Строя` (у «Ветер» выпадает «е»). Такое название остаётся в тексте открытым.
- Название заглавными без формы: `КАМЕННЫЙ МОСТ прислал письмо`. С формой (`КАМЕННЫЙ МОСТ ООО`) связывается.
- Транслит и сокращения: `Kamenniy Most`, `КМ`.
- Название, которого нет ни в документе с формой, ни в сейфе: без формы правила его не находят. Его надо вписать в «Что ещё спрятать».
- Адрес в другом порядке: `Балканская ул., д.20` против `ул. Балканская, д. 20` получат разные метки.
- Номер с другой записью: `41КВ/2025` против `41-КВ/2025`.
- Имя и отчество без фамилии (`Олег Петрович`) не связываются с полным ФИО.
- Слово с заглавной в начале предложения перед именем правила ФИО принимают за фамилию: в `Подписал И.С. Петров` меткой станет «Подписал И.С.», а `Петров` получит метку человека из сейфа. Так было и до сейфа.
- Одинокая фамилия, если в сейфе два человека с этой фамилией. Метку она не получает и остаётся в тексте открытой.
- Склейка, а не расщепление: два человека с одной фамилией и одной буквой имени (`Петров Иван` и `Петров Игорь`) получают одну метку. Номера документов из одних цифр (`№ 214` платёжки и `№ 214` счёта) тоже. Это было и внутри одного документа, с сейфом то же действует между документами.

## Обратная подстановка

`safeRestore(текст, сейф)` ищет метки и меняет известные сейфу на значение записи. Узнаются искажения, которые делает нейросеть:

- регистр: `[орг_1]`, `[Фио_1]`;
- пробел или дефис вместо подчёркивания и пробелы в скобках: `[ОРГ 1]`, `[ ОРГ_1 ]`, `[ОРГ1]`;
- «е» вместо «ё»: `[СЧЕТ_1]`;
- экранирование Markdown: `\[ОРГ\_1\]`;
- без скобок: `ОРГ_1`, `орг_1`, `ФИО-1`. Без скобок и через пробел (`ОРГ 1`) метка меняется, только если слово заглавными и метка есть в сейфе;
- старые метки `#ORG_1#`, если они есть в сейфе.

Не трогаются:

- обычный текст: `ИНН 7816135799`, `счёт 1`, `Счёт 60`, `договор 1`. Номер метки до четырёх цифр;
- метка, которой нет в сейфе. Если она в скобках или с подчёркиванием, страница подсвечивает её рамкой и пишет «нет в сейфе»;
- метка с окончанием `[ОРГ_1]у`, `[ФИО_1]а`. Склонять название автомат не умеет, страница подсвечивает такую метку и пишет «впишите сами». Это отложено в плане.

Подстановка идёт по текущему сейфу и работает без документа: открыть сейф, вставить ответ, нажать «Вернуть данные».

## Страница

- Над документом панель «Сейф». Если сейф не открыт и пуст, панель с красной полосой: «не загружен. Если по этому клиенту или делу уже есть сейф, откройте его: тогда метки совпадут с прежними документами. Без сейфа Маска начнёт новый.» Дальше она показывает название, число записей и своих слов, дату изменения и «сохранён» или «не сохранён».
- «Открыть сейф» выбирает файл. Файл `.json`, перетащенный на страницу или выбранный кнопкой «Загрузить файл», тоже открывается как сейф.
- Битый или чужой файл: «Не удалось открыть сейф «имя»: причина. Текущий сейф не изменился.»
- Если в текущем сейфе есть записи или слова, другой сейф и «Начать новый сейф» сначала показывают вопрос на странице: «Заменить сейф «А» (записей N) на «Б» (записей M)?», с предупреждением, если текущий не сохранён. Кнопки «Заменить» и «Оставить текущий». Сейфы не смешиваются: замена полная. Документ на экране перемаскируется с новым сейфом.
- «Сохранить сейф» скачивает файл. После каждого документа, если сейф изменился, над кнопками скачивания стоит напоминание «Сохраните сейф» с числом новых записей. При закрытии вкладки с несохранённым сейфом браузер спросит подтверждение.
- Поле «Что ещё спрятать» показывает слова сейфа. Слово, удалённое из поля, удаляется из сейфа при следующей маске.
- Сейф живёт в памяти страницы и в файле. В `localStorage`, `sessionStorage`, IndexedDB и cookie страница ничего не пишет, это проверяет `tests/page.test.mjs`.

## Что изменилось в записи файлов

Код записи (`src/zip.mjs`, `src/ooxml.mjs`, `src/xlsx-return.mjs`, `src/docx-return.mjs`, план замены в `src/office.mjs`) в этой работе не менялся. Изменилось то, что в него приходит.

1. Текст метки. Вместо `#ORG_1#` в файл пишется `[ОРГ_1]`: кириллица, квадратные скобки, подчёркивание. Это касается всех мест, куда Маска пишет метку: абзацы и таблицы docx, колонтитулы, сноски, примечания, надписи, поля (в том числе `HYPERLINK "mailto:[ПОЧТА_1]"`), свойства файла; в xlsx общие строки, строки в ячейках, ячейки, где число стало текстом, примечания, надписи, колонтитулы листа; csv, md и txt.
2. Больше замен в файле с открытым сейфом. Написания из сейфа, названия без формы и падежные формы названий попадают в список замен. На 39 настоящих файлах находок в сеансе с одним сейфом 3829 против 3725 без сейфа, правок по месту и чисел, ставших текстом, столько же: 603 и 193.
3. Новые ключи почты, адреса и суммы меняют только номер метки, способ записи тот же.

Проверено на Node, без Word и Excel:

- ячейка с меткой в xlsx записана общей строкой (`t="s"`), строкой в ячейке (`t="inlineStr"`) или строкой формулы (`t="str"`), числом или формулой нет. На настоящих файлах 636 ячеек с меткой на листах, все строкой. Метка не начинается с `=`, `+`, `-` или `@`, поэтому csv в Excel формулой её тоже не прочтёт. Внутри `<f>` меток нет, формулы побайтно те же;
- кусков `<r>` с пустым `<t>` 0 во всех xlsx: в наборах, в сквозном тесте и в 18 настоящих книгах;
- архив и все XML-части разбираются, нетронутые записи zip побайтно те же (`tests/real-check.mjs`);
- в колонтитулах листа метка стоит после кода `&L`, `&C` или `&12`. Скобка не цифра и не буква, Excel не примет её за код.

Квадратная скобка в md: метка вплотную перед круглой скобкой (`[ОРГ_1](Подрядчик)`, если в исходнике не было пробела) в Markdown читается как ссылка. В тексте нейросеть её всё равно увидит, на возврат это не влияет.

## Стенд

`tests/harness-files.mjs` ведёт сеанс: файлы идут по порядку разметки с одним сейфом. Разметка `tests/deal.json` стала объектом `{entities, files}`, старый вид (список файлов) стенд читает как раньше. `entities` это словарь из 86 сущностей сделки: `{"id": "org-kamennyj-most", "type": "организация", "forms": ["Общество с ограниченной ответственностью «Каменный Мост»", "ООО «Каменный Мост»"]}`.

Для каждого места, где написание сущности стоит в тексте файла, стенд берёт метки находок, которые его покрывают. Счётчики:

- доля сущностей с одной меткой во всех файлах (все места спрятаны, метка одна, её нет у другой сущности), отдельно для сущностей, которые встречаются в двух файлах и больше;
- расщеплённые: одна сущность, несколько меток, со списком файлов и меток;
- склеенные: одна метка у разных сущностей;
- места, где написание осталось открытым.

`--fresh` даёт новый сейф на каждом файле, как было до сейфа. `--session` включает сеанс для разметки без словаря. `tests/roundtrip.mjs --session` возвращает папку файлов одним сейфом.

`tests/deal/make.py` словарь не пишет. Разметка `tests/deal.json` правлена после него и раньше (даты в `keep`), при пересборке набора словарь и эти правки надо перенести.

## Что проверить руками

В браузере (здесь его нет, интерфейс проверен на заглушке DOM):

1. Открыть `index.html` с диска. Панель «Сейф» с предупреждением «не загружен».
2. Обезличить `tests/deal/dogovor-podryada.docx`, вписать название сейфа, нажать «Сохранить сейф». Скачается `<название>.сейф.json`.
3. Обновить страницу, перетащить сейф, затем `akt-sdachi-priemki.docx` и `akt-sverki-1c.xlsx`. «Каменный Мост» во всех трёх стоит под одной меткой, в таблице меток у неё нет пометки «новая».
4. Перетащить чужой `.json` и битый файл: сообщение, сейф прежний.
5. Перетащить другой сейф: вопрос на странице, «Оставить текущий» и «Заменить».
6. Закрыть вкладку с несохранённым сейфом: браузер спросит подтверждение.
7. Вставить ответ с метками `[орг_1]`, `ОРГ_1`, `[ОРГ_9]`, `[ОРГ_1]у`: первые две заменятся, две последние подсвечены рамкой.
8. Вкладка «Сеть» в инструментах разработчика пуста, «Хранилище» (Local Storage, Session Storage, IndexedDB) пусто.

В Word и Excel: открыть возвращённые файлы сеанса из `out/deal-session/` (`node tests/roundtrip.mjs tests/deal --session --out out/deal-session`): `dogovor-podryada-maska.docx`, `akt-sdachi-priemki-maska.docx`, `akt-sverki-1c-maska.xlsx`, `osv-60-maska.xlsx`, `reestr-dogovorov-maska.xlsx`. Нет сообщения о повреждении, метки `[ОРГ_1]` видны как текст, в ячейках слева, как текст. Колонтитулы и примечания с метками на месте. Excel для Mac обязателен: LibreOffice пустые куски `<r>` не ловил.
