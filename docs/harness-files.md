# Стенд на файлах: tests/harness-files.mjs

Стенд меряет Маску на настоящих docx, xlsx, csv, md и txt. Файлы читаются тем же `readOffice` из `src/office.mjs`, что встроен в index.html (описание в docs/reading-and-return.md), mask берётся из index.html, как в harness.mjs. С `--index` на старую версию index.html, где ещё есть readDocx и readXlsx, стенд вырезает их по границам функций и подменяет DOMParser маленьким разборщиком XML, как раньше.

## Запуск

```
node tests/harness-files.mjs <папка с файлами> <разметка.json>
node tests/harness-files.mjs <папка> <разметка.json> --json files-2026-10-04.json
node tests/harness-files.mjs --find <файл> [--save]
```

Параметр `--index путь` подставляет другой index.html, например старую версию.

Проверка самого стенда на синтетическом наборе:

```
node tests/harness-files.mjs tests/files tests/files.json
```

Файлы без записи в разметке не считаются, их имена стенд печатает в конце.

## Формат разметки

Список объектов. Поля `file`, `must`, `keep`, `types` работают как в harness.mjs. Новое поле `must_types` задаёт строки и их тип данных. Строки из `must_types` считаются обязательными, дублировать их в `must` не нужно. Старые файлы разметки без `must_types` работают как раньше.

```json
[
 {
  "file": "dogovor.docx",
  "must": ["Игнатьев С.Б."],
  "must_types": {
   "Захарченко Тимура Рустамовича": "фио",
   "5074012345": "инн",
   "РД-2026/0417": "номер_договора"
  },
  "keep": ["Предмет договора", "акта сдачи-приёмки"],
  "types": {"+7 (495) 318-27-64": "PHONE"}
 }
]
```

Допустимые типы в `must_types`: фио, организация, инн, счёт, телефон, почта, адрес, номер_договора, сумма, дата, прочее. Другое слово стенд принимает, но печатает предупреждение. Поле `types` осталось прежним: там внутренние типы Маски (PERSON, PHONE, INN и так далее), проверяется метка на месте значения.

Строки для xlsx пишите так, как они выглядят в извлечённом тексте. Число в ячейке приходит как есть (`1284500.5`, `32581` вместо даты). Посмотреть этот текст можно через `--find`.

Разметка может быть объектом `{"entities": [...], "files": [...]}`: `files` это тот же список, `entities` словарь сущностей `{"id", "type", "forms"}` для сеанса с одним сейфом. Сеанс идёт сам, если словарь есть, или с `--session`; `--fresh` даёт новый сейф на каждом файле. Счётчики сеанса описаны в docs/safe.md.

## Что считается

- По каждому файлу: спрятано из must, задето из keep (строка keep пропала из результата или тип метки не тот).
- Итог: спрятано N/M в процентах и не задето K/L.
- Таблица «тип: спрятано из скольких» по строкам из `must_types`.
- Строка считается спрятанной, если её нет в `mask().masked`. Проверка подстрокой, как в harness.mjs.

## Режим --json

Записывает файл с полями: дата, sha256 всего index.html, итог, разбивка по типам, список по файлам (спрятано, пропущенное, задетое). Пропущенные строки лежат как есть, то есть с настоящими данными. Путь без каталога уходит в `out/` (папка в .gitignore). Если указать путь в другом месте, стенд запишет туда, так что такие файлы в репозиторий класть нельзя.

## Режим --find

Печатает извлечённый текст с номерами строк, под строкой с находками пишет значение и внутренний тип Маски, в конце список всех находок. Это заготовка для разметки: то, что нашлось, идёт в `must_types`, а то, что Маска пропустила, человек или агент добавляет сам. С `--save` вывод пишется в `out/find-<имя файла>.txt`. Без него только в консоль.

## Синтетический набор

В `tests/files/`: два docx и два xlsx с выдуманными данными, разметка в `tests/files.json`. Writer в LibreOffice на этой машине не установлен, поэтому docx собраны вручную из XML через zipfile (таблица, верхний и нижний колонтитулы, абзацы из нескольких фрагментов текста). Оба xlsx сделаны через `soffice --convert-to xlsx` из flat ODS: в одном два листа и ИНН числом, в другом даты, число-оклад и формула. ИНН посчитаны с верной контрольной суммой.

Замер на 04.10.2026: спрятано 37/53, не задето 15/16.

| тип | спрятано |
|-----|----------|
| фио | 10/10 |
| организация | 5/5 |
| инн | 4/6 |
| счёт | 6/6 |
| телефон | 7/7 |
| почта | 4/4 |
| адрес | 1/1 |
| номер_договора | 0/5 |
| сумма | 0/5 |
| дата | 0/4 |

Пропуски относятся к самой Маске, а не к чтению файлов. Десятизначный ИНН без слова «ИНН» рядом (ячейка xlsx) не находится, двенадцатизначный находится. Номера договоров, суммы и даты Маска не прячет. Шапка таблицы «Контрагент	ИНН» (два слова через табуляцию) распознаётся как фамилия и имя: это ложное срабатывание, оно видно как «задето лишнее». Название организации в колонтитуле «Ромашкин Двор, тел. …» получает метку PERSON.

## Находки: что теряли readDocx и readXlsx

Большая часть закрыта новым чтением, список закрытого и оставшегося в docs/reading-and-return.md.

Проверено на файлах, собранных вручную (вне набора), и по коду. Исправления в index.html не вносились.

docx:

- Сноски и концевые сноски (`word/footnotes.xml`, `endnotes.xml`) не читаются, текст теряется.
- Примечания (`word/comments.xml`) не читаются.
- Элементы управления содержимым (`w:sdt`) на верхнем уровне тела документа пропускаются целиком: обход идёт только по `w:p` и `w:tbl`, прямые дети body. Так часто устроены титульные листы и поля шаблонов.
- Надписи (текстовые поля) дублируются: Word пишет их дважды, в `mc:Choice` и `mc:Fallback`, и читаются оба. Утечки нет, но текст задвоен, и метки пойдут по два раза на одно значение.
- Вложенные таблицы дублируются: строки внутренней таблицы попадают и в ячейку внешней, и отдельными строками.
- Колонтитулы читаются все (header и footer, включая первую страницу), но кладутся в конец документа. Колонтитул, состоящий только из цифр или «стр. N», выбрасывается.
- Удалённый tracked-текст (`w:delText`) не читается, вставленный читается. Это верное поведение для «что увидит пользователь после принятия правок», но вставки и удаления нигде не помечены.
- Не проверялось: текст в SmartArt и диаграммах, поля формул, текст в `w:drawing` вне надписей.

xlsx:

- Названия листов приписываются по номеру файла `sheetN.xml`, а не по связям `workbook.xml.rels`. Если листы переставлены, подписи «Лист «…»» стоят не у тех данных. Проверено: лист «Вторая» подписан над содержимым другого листа.
- Скрытые листы читаются без пометки. Для обезличивания это плюс, но человек в браузере их не видит.
- Примечания к ячейкам (`xl/comments*.xml`, в том числе потоковые комментарии) не читаются.
- Надписи и фигуры на листах (`xl/drawings`), колонтитулы листа, текст в диаграммах не читаются. Это найдено по коду, без отдельного файла.
- Даты приходят числом дней (`32581` вместо 14.03.1989): Маска их не узнаёт. Подсказка в info срабатывает только при слове «дата» в первых трёх строках текста и называет пример, а не реальные значения.
- Числа в ячейках приходят «как хранятся»: большое число может прийти в экспоненциальной записи (`4.0702810300000046E+19`), у 20-значного счёта, записанного числом, хвост потерян ещё в самом файле. ИНН числом читается нормально.
- Лимит 400 строк на всю книгу: остальное отбрасывается, об этом говорит только строка info.
- Формулы читаются как последнее вычисленное значение. Если файл не пересчитан, значение может быть пустым или устаревшим. Ячейка с ошибкой даёт `#VALUE!` и подобное.
- Пустые ячейки между значениями становятся пустыми колонками через табуляцию (не потеря, но строки получаются с лишними табуляциями).
